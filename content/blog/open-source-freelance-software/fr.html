Pourquoi l’open source compte pour une petite entreprise

Open source signifie que le code est public et publié sous une licence qui permet à chacun de l’utiliser, de le modifier et de l’exécuter. Pour un freelance, c’est moins une question d’idéologie que de cinq protections concrètes.

Vos données vous appartiennent

Avec un logiciel open source, vous pouvez toujours voir comment vos données sont stockées, et rien ne vous empêche de faire tourner une copie dont vous contrôlez la base de données. Vos clients et vos factures ne dépendent pas du bon vouloir d’une seule entreprise.

Pas d’enfermement

Si l’outil ne vous suffit plus, ou si vous voulez simplement partir, le format de vos données est documenté dans le code lui-même. Partir devient un projet, pas une prise d’otage.

Vous pouvez l’héberger vous-même

Si vous le souhaitez, vous pouvez faire tourner le logiciel sur vos propres comptes. Certains freelances le font pour la confidentialité, d’autres pour le coût, d’autres parce qu’un contrat client l’exige. La plupart ne le font jamais, mais avoir cette possibilité change la relation avec l’éditeur.

Vous pouvez inspecter le code

Vous, un ami développeur ou l’équipe sécurité d’un client pouvez lire comment un lien est partagé, ce qu’un client peut voir et où un fichier est stocké. Vous n’avez pas à croire une page marketing sur parole.

Le prix ne peut pas être pris en otage

Une offre hébergée peut toujours augmenter. Mais quand le logiciel lui-même est libre d’utilisation, l’éditeur sait que vous pouvez partir en emportant le même outil. Cela garde les prix honnêtes. Pour un freelance qui a bâti cinq ans de méthodes de travail autour d’une seule application, c’est l’avantage le plus sous-estimé.

Ce qu’il faut vérifier

« Open source » sur une page d’accueil, c’est un début, pas une garantie. Avant de confier votre activité à un outil, vérifiez ces points :

  • La licence. Les licences permissives comme MIT vous permettent d’utiliser, de modifier et d’héberger le logiciel pour n’importe quel usage, y compris commercial. Certaines licences « source disponible » le restreignent : lisez le fichier de licence.
  • Le code est réellement public, dans un dépôt que vous pouvez ouvrir, et non « disponible sur demande ».
  • Une documentation d’auto-hébergement existe et décrit une vraie installation de production, pas seulement une démo locale.
  • Vous pouvez exporter vos données depuis la version hébergée aussi, dans un format comme le CSV.
  • La version hébergée est le même logiciel. Si le cloud payant a des fonctions que le code ouvert n’a pas, vous revoilà enfermé.
  • Il fait le travail. L’open source ne compense pas les fonctions manquantes. Vérifiez que les propositions, les contrats et les factures fonctionnent comme vous travaillez.
  • Il est toujours maintenu. Regardez quand le code a changé pour la dernière fois et si les mises à jour sont accompagnées d’instructions.

Les vrais compromis de l’auto-hébergement

Héberger vous-même votre logiciel de gestion est une vraie responsabilité. Avant de faire ce choix, sachez clairement à quoi vous vous engagez :

  • C’est vous qui le maintenez. Les mises à jour, les sauvegardes et les réparations quand un fournisseur change quelque chose sont votre affaire. Personne d’autre ne surveille votre copie à 2 h du matin.
  • Il vous faut des comptes chez des fournisseurs d’infrastructure. Pour Thrive, cela veut dire un compte Cloudflare et un projet Supabase. Leurs offres et leurs coûts d’utilisation se règlent entre vous et eux.
  • Il vous faut une certaine aisance technique. Vous utiliserez un terminal, modifierez un fichier de configuration, définirez des secrets et lirez des messages d’erreur. Si « lancer npm test » ne vous dit rien, la version hébergée est sans doute le meilleur choix.
  • Les sauvegardes sont à votre charge. Vos factures et vos contrats signés sont des documents comptables et commerciaux. Une copie que vous ne savez pas restaurer n’est pas une sauvegarde.
  • L’e-mail et l’agenda demandent une configuration supplémentaire. Connecter des boîtes mail et des agendas nécessite en général vos propres comptes chez un fournisseur, plus leurs processus de validation.

Pour la plupart des freelances, la voie raisonnable est la suivante : utiliser la version hébergée, et apprécier de pouvoir s’auto-héberger si un jour c’était nécessaire.

Auto-hébergé : gratuit sous licence MIT

Vous pouvez faire tourner le même code sur vos propres comptes. Le guide d’auto-hébergement de Thrive (docs/self-hosting.md dans le dépôt) décrit une installation sur Cloudflare Workers avec Supabase pour la connexion, la base de données et le stockage privé des fichiers. En résumé :

  1. Créez un projet Supabase et appliquez une fois, dans l’ordre, les fichiers de migration SQL du dépôt. Activez la connexion par e-mail et mot de passe, définissez l’adresse de votre site et les URL de redirection, et configurez votre propre service SMTP pour les e-mails d’inscription et de mot de passe.
  2. Configurez le Worker. Avec Node.js 22.13 ou plus récent, installez et lancez les tests, puis indiquez le nom de votre Worker, l’adresse de votre application et votre URL Supabase dans wrangler.self-hosted.jsonc.
  3. Compilez et déployez avec Wrangler, puis ajoutez vos deux clés Supabase comme secrets du Worker. Utilisez l’adresse workers.dev du Worker ou rattachez votre domaine.
  4. Options supplémentaires. L’e-mail, l’agenda et les pages de réservation nécessitent votre propre compte Nylas. Pour connecter Claude ou ChatGPT, activez le serveur OAuth de Supabase comme le décrit le guide.
  5. Vérifiez et sauvegardez. Le guide comprend une checklist : inscription et connexion, données enregistrées d’un navigateur à l’autre, liens client qui cessent de fonctionner une fois révoqués, et sauvegardes de la base de données comme des fichiers stockés.

Le dépôt contient aussi une invite de configuration que vous pouvez confier à un agent de code pour qu’il vous accompagne dans l’installation. Une copie auto-hébergée convient à une personne, ou à plusieurs personnes avec des espaces de travail séparés ; il n’y a pas de gestion des droits pour une équipe partagée. La facturation de l’abonnement est désactivée dans une installation auto-hébergée.
