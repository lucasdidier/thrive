# Thrive

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users and purpose

Independent service businesses managing their clients and project work from inquiry to payment. This audience and workflow are recorded in the existing product brief and implementation; they were not re-researched in this visual exploration.

## Operating context

A connected workspace for clients, projects, proposals, contracts, invoices, email, scheduling, time, forms, and workflows. Daily operations must remain recognizable across list views, detail panels, and creation drawers. Monetary totals come from business records.

## Capabilities and constraints

Preserve existing workflows, validation, immutable commercial snapshots, account boundaries, and saved workspace data. Client document branding is independent of the application theme. UI exploration uses fictional sample records in an isolated local preview, with no external sends or provider connections.

## Brand commitments

Thrive keeps its name and existing outline mark. The user requested a visual revamp closely informed by LAGO and Attio, with blue primary actions. On October 29, 2026, the user selected light-first appearance with matching dark mode. Existing explicit dark/light preferences remain respected.

## Evidence

Current implementation: `public/`, `ui/`, `fluid/`. The seed dataset is fictional and must not be represented as customer proof.

## Principles

Keep client context connected to the work. Make the next useful action clear. Use consistent patterns across records. Keep configuration inspectable. Preserve keyboard access, readable contrast, responsive layouts, and reduced-motion support.
